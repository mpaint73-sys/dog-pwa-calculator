# План: оффлайн PWA с localStorage для калькулятора пайки

**Проект:** `DOG-PAIKA` — одностраничный калькулятор натуральной пайки для собак (GitHub Pages).  
**Текущее состояние:** `index.html` (всё в одном файле), базовый Service Worker, `manifest.json`, картинка `splash-bullterrier.jpg`.  
**Чего нет:** localStorage, профилей собак, журнала покупок, слайдеров процентов, рабочих иконок PWA (в manifest указаны `icon-192.png` / `icon-512.png`, но файлов нет).

---

## Цели

| # | Требование | Результат |
|---|------------|-----------|
| 1 | Профили собак | Вкладки с кличкой; можно считать без сохранения или сохранить «свою» собаку |
| 2 | Журнал покупок | Записи с датой: что куплено, сколько кг, сколько ₽ |
| 3 | Иконка на главном экране | Из `splash-bullterrier.jpg` (192×192, 512×512) |
| 4 | Мобильное PWA | Удобный UX на телефоне, оффлайн после первого визита |
| 5 | Слайдеры процентов | Ползунок + поле ввода, синхронно |
| 6 | Деплой на GitHub | Инструкция обновления Pages |

## Архитектура данных (localStorage)

Один ключ `dogPaikaData` (JSON), версия схемы `version: 1` для миграций.

```json
{
  "version": 1,
  "activeDogId": "uuid-или-null",
  "dogs": [
    {
      "id": "uuid",
      "name": "Барсик",
      "createdAt": "2026-06-13T10:00:00.000Z",
      "updatedAt": "2026-06-13T12:00:00.000Z",
      "params": {
        "weight": 10,
        "ageGroup": "18+",
        "meals": 2,
        "pctBody": 3
      },
      "components": [40, 30, 20, 10],
      "preset": "classic",
      "costPrices": { "meat": 350, "muscle": 200, "bone": 80, "secreting": 150 },
      "daysCount": 30
    }
  ],
  "purchases": [
    {
      "id": "uuid",
      "dogId": "uuid",
      "date": "2026-06-10",
      "items": [
        { "componentId": "meat", "kg": 5, "pricePerKg": 350, "total": 1750 }
      ],
      "totalAmount": 1750,
      "note": ""
    }
  ],
  "settings": {
    "paramsCollapsed": true
  }
}
```

**Правила:**
- Вкладка «Быстрый расчёт» — `activeDogId = null`, данные только в памяти, при уходе не сохраняются (или спросить «Сохранить?»).
- Сохранённая собака — полный снимок параметров + процентов + цен за кг.
- Покупки привязаны к `dogId`; в журнале фильтр по активной собаке или «все».

**API в коде (модули в `<script>`):**
- `loadData()` / `saveData()` — чтение/запись с try/catch и fallback на пустую структуру
- `createDog(name)` / `updateDog(id, patch)` / `deleteDog(id)`
- `addPurchase(dogId, purchase)` / `deletePurchase(id)`
- `exportData()` / `importData(json)` — опционально, для бэкапа

## Этап 1. Навигация и профили собак

### 1.1 Верхняя панель вкладок (mobile-first)

```
[ ⚡ Быстрый ] [ 🐕 Барсик ] [ 🐕 Рекс ] [ + ]
```

- Горизонтальный скролл на узком экране (`overflow-x: auto`, `scroll-snap`).
- Safe area: `padding-top: env(safe-area-inset-top)`.
- Активная вкладка — подчёркивание цветом `#b8860b`.

### 1.2 Создание / редактирование профиля

- Кнопка «+» → модалка: поле «Кличка», кнопки «Сохранить» / «Отмена».
- На вкладке сохранённой собаки — иконка ✏️ (переименовать) и 🗑️ (удалить с подтверждением).
- Кнопка **«Сохранить собаку»** на вкладке быстрого расчёта (если введены параметры) → создаёт профиль из текущих значений.
- Кнопка **«Сохранить изменения»** на вкладке собаки — обновляет профиль при изменении полей.

### 1.3 Автосохранение vs явное сохранение

Рекомендация для UX:
- **Быстрый расчёт:** без автосохранения.
- **Вкладка собаки:** автосохранение с debounce 500 ms после изменения любого поля (удобно на телефоне).

### 1.4 Переключение вкладок

При смене вкладки:
1. Если уходим с «Быстрого» — ничего не пишем в storage.
2. Если уходим с собаки — flush debounced save.
3. Загружаем `params`, `pcts`, цены, `daysCount` в форму и вызываем `calculate()`.

## Этап 2. Журнал покупок

### 2.1 UI — новая карточка «История покупок»

Расположение: под блоком «Расчёт на период + стоимость» или отдельная подвкладка «Покупки» внутри профиля собаки.

**Форма добавления записи:**
| Поле | Тип |
|------|-----|
| Дата | `<input type="date">` (по умолчанию сегодня) |
| Продукт | select из 4 компонентов + «Другое» |
| Кг | number, step 0.1 |
| ₽/кг или сумма | number (пересчёт total) |
| Комментарий | text, опционально |

Кнопка «Добавить покупку».

**Список записей:**
- Сортировка по дате (новые сверху).
- Группировка по месяцам (заголовок «Июнь 2026»).
- Строка: `10.06 · 🥩 Мясо · 5 кг · 1 750 ₽` + кнопка удалить.
- Итого за месяц / за всё время (опционально).

### 2.2 Связь с расчётом

- При добавлении покупки можно подставить `pricePerKg` в поле цены соответствующего компонента (чекбокс «Обновить цену в расчёте»).
- Журнал виден только если выбрана сохранённая собака; на «Быстром расчёте» — подсказка «Сохраните собаку, чтобы вести историю покупок».

## Этап 3. Слайдеры для процентов компонентов

### 3.1 Разметка каждого компонента

Заменить только `pct-input` на связку:

```html
<div class="pct-control">
  <input type="range" class="pct-slider" min="0" max="100" step="1" value="40">
  <input type="number" class="pct-input" min="0" max="100" step="1" value="40">
  <span class="pct-sign">%</span>
</div>
```

Визуальная полоска `bar-fill` уже есть — обновлять при движении слайдера.

### 3.2 Стили (мобильные)

- `pct-slider`: высота touch-target ≥ 44px (увеличить область нажатия через padding).
- Цвет thumb/track в палитре компонента (`accent-color` или кастомный `-webkit-slider-thumb`).
- На экранах &lt; 480px: слайдер на всю ширину блока `.info`, число справа.

### 3.3 Логика

- `onPctSlider(input)` и `onPctChange(input)` вызывают общую `setPct(idx, value)`.
- При пресетах — обновлять и слайдеры, и inputs.
- Сумма ≠ 100% — текущая индикация (ok/warn/err) без изменений.

### 3.4 Опционально: «умный» слайдер

При движении одного ползунка остальные пропорционально подстраивать до 100% — **не делать в v1** (сложно на мобильном). Оставить ручную настройку + пресеты.

## Этап 4. PWA: иконка и оффлайн

### 4.1 Генерация иконок из `splash-bullterrier.jpg`

**Задача:** создать `icon-192.png` и `icon-512.png`.

Варианты:
1. **Онлайн / GIMP / Photoshop** — экспорт квадрат 192 и 512 (центрировать собаку, обрезать).
2. **Скрипт** (Node + `sharp` или Python + Pillow) в папке `scripts/generate-icons.js` — один раз запустить локально.

Дополнительно для iOS:
- `apple-touch-icon` в `<head>`: `icon-192.png`
- `<link rel="icon" href="icon-192.png">`

### 4.2 Обновить `manifest.json`

```json
"icons": [
  { "src": "icon-192.png", "sizes": "192x192", "type": "image/png", "purpose": "any" },
  { "src": "icon-512.png", "sizes": "512x512", "type": "image/png", "purpose": "any" },
  { "src": "icon-512.png", "sizes": "512x512", "type": "image/png", "purpose": "maskable" }
]
```

### 4.3 Обновить `sw.js`

- Версия кэша: `dog-pwa-v2` (при каждом релизе увеличивать).
- Список `urlsToCache`:
  - `./index.html`
  - `./manifest.json`
  - `./icon-192.png`
  - `./icon-512.png`
  - `./splash-bullterrier.jpg` (если используется как splash в UI)

- Стратегия: **cache-first** для статики, **network-first** не нужен (приложение полностью клиентское).
- localStorage Service Worker не кэширует — данные живут в браузере автоматически.

### 4.4 Проверка установки на телефон

**Android (Chrome):** меню → «Установить приложение» / «Добавить на главный экран».  
**iOS (Safari):** «Поделиться» → «На экран Домой».  
Иконка = `icon-192.png` / apple-touch-icon.

## Инструкция: обновление на GitHub Pages

### Предварительно

- Репозиторий на GitHub (например `username/dog-pwa-calculator`).
- В **Settings → Pages**: Source = `Deploy from a branch`, Branch = `main` / `/ (root)`.

### Шаги деплоя

1. **Сгенерировать иконки** локально из `splash-bullterrier.jpg` → положить `icon-192.png` и `icon-512.png` в корень репозитория.

2. **Увеличить версию кэша** в `sw.js`:
   ```js
   const CACHE_NAME = 'dog-pwa-v2'; // было v1
   ```

3. **Закоммитить все файлы:**
   ```bash
   cd D:\cursor\DOG-PAIKA
   git add index.html manifest.json sw.js icon-192.png icon-512.png splash-bullterrier.jpg grok.md
   git commit -m "PWA: localStorage, профили собак, журнал покупок, слайдеры, иконки"
   git push origin main
   ```

4. **Дождаться деплоя** (1–3 мин). Проверить Actions/Pages в репозитории — зелёный статус.

5. **На телефоне обновить приложение:**
   - Если уже установлено PWA: закрыть приложение полностью, открыть сайт в браузере по URL, подождать обновление SW (или очистить данные сайта один раз).
   - Удалить старую иконку с главного экрана и установить заново — если иконка не обновилась (кэш ОС).
   - **Важно:** localStorage привязан к origin (`https://username.github.io`). Данные сохраняются между визитами и не теряются при обновлении кода, пока не меняется домен/путь.

6. **Проверка localStorage:**
   - Открыть сайт → создать собаку → перезагрузить страницу → вкладка и данные на месте.
   - Chrome DevTools → Application → Local Storage → ключ `dogPaikaData`.

7. **Проверка оффлайн:**
   - Открыть сайт онлайн (один раз).
   - Включить авиарежим → приложение открывается и считает; данные из localStorage доступны.

### Если Pages не обновляется

- Жёсткое обновление в браузере: Ctrl+Shift+R (или очистка кэша сайта).
- Проверить, что `sw.js` отдаётся с новым `CACHE_NAME`.
- В Chrome: DevTools → Application → Service Workers → «Unregister», затем перезагрузить.

### HTTPS

GitHub Pages отдаёт по HTTPS — Service Worker и `localStorage` работают только так (на `file://` не заработают).

## Риски и ограничения

| Риск | Митигация |
|------|-----------|
| Переполнение localStorage (~5 MB) | Журнал покупок растёт медленно; при необходимости — экспорт/очистка старых записей |
| iOS удаляет данные через 7 дней без визита | Предупредить в «О приложении»; PWA на Home Screen снижает риск |
| Синхронизация между устройствами | Нет в v1 (только локально); export/import JSON — запасной план |
| Сумма процентов ≠ 100% | Оставить явное предупреждение, не блокировать ввод |
